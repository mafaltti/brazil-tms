# Implementation Plan: Driver CPF Replaces E-mail

**Branch**: `022-driver-cpf-field` | **Date**: 2026-07-28 | **Spec**: [spec.md](./spec.md)

## Summary

Issue #28 [0005]: replace the driver form's E-mail field with CPF. Contained swap across the six
files that carry driver e-mail: shared Zod (`driverBase.email` → `cpf` via a new `cpfSchema`,
11-digits-after-strip mirroring `cnpjSchema`), Drizzle schema (add `cpf` column; `email` column
stays mapped but **dormant** — kept so drizzle-kit never diffs a DROP), migration 0009
(`ADD COLUMN cpf text` only — no data loss), drivers service (DTO/insert/update field list),
driver form + detail client, pt-BR catalog. PRD §14/RES-002/§30 amended.

## Technical Context

**Migration**: `0009` generated by `drizzle-kit generate` — additive only. The dormant `email`
column keeps its Drizzle mapping (with a comment) precisely so future `generate` runs stay clean;
it is simply never selected into the DTO nor accepted by the schemas.

**Testing**: Vitest — `cpfSchema` normalization/rejection + driver schema shape (shared);
cpf round-trip + clear semantics in `resources-service.test.ts` (needs local Postgres 5433).
E2e — extend `master-data-resources.spec.ts`: create-driver fills CPF, asserts no "E-mail" label.

**Everything else**: unchanged — no permission, search, worker, or picker touches e-mail today.
