# Implementation Plan: Documents, Completion, Billing Readiness, Rates, and Export

**Branch**: `008-documents-billing-export` | **Date**: 2026-06-01 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/008-documents-billing-export/spec.md`

## Summary

This slice is the **proof-and-money close-out** over the trip domain: operations and finance attach **proof-of-execution documents** (POD, CT-e/MDF-e references, gate receipts) and **verify** them (accepted / rejected / pending review); the system **gates Completed and Billing Ready** on the per-customer **required-document checklist** + pricing + dispute rules; finance maintains **simple rates** (customer / lane / vehicle type / effective date) and a transparent **billable breakdown** (typed tolls / waiting time / redelivery / extra stops / penalties / discounts / manual adjustments → planned / executed / adjustment / final value); and finance **exports** billing-ready trips to CSV/spreadsheet with durable **export-batch history**. It fills slice 005's reserved Trip-Detail documents/billing placeholders, the "Completed trips missing documents" dashboard widget, and the "Missing documents" board view; and it lights up the **two §17 alert cases** (completed-but-missing-documents, billing-blocked-by-missing-proof) that slice 007 deferred.

Technical approach: 008 adds **seven new tables** — `document_types` (a configurable proof-type master, clarify Q2), `documents`, `document_requirements`, `rates`, `billing_items`, `billing_adjustments` (the BILL-004 typed line table), `export_batches` (mirrors 004's `import_batches`) — plus **three new pgEnums** (`document_verification_status`, `export_batch_status` mirroring `import_batch_status`, `billing_adjustment_type`); `export_batches.format` / `billing_items.dispute_status` are **CHECK text**, `document_types` is a **config table** (not an enum). Crucially there is **no `trips` ALTER**: billing lifecycle status is the **`billingStatus(current_status)` projection** slice 003 already defines (FR-011), and the new tables FK *to* `trips`. **Completion and Billing Ready are transitions on the existing 003 status machine**: `markCompleted` / `markBillingReady` gather context, call the **pure** `evaluateCompletionReadiness` / `evaluateBillingReadiness` (`@brazil-tms/shared`, the §19.3/§19.4 gates — STACK §3.13 names billing-readiness a Vitest focus), and drive the change through the **reused `transitionTripStatus`** (concurrency guard + `trip_events` + `trip.status_change` audit + in-tx `recomputeTripSla`) — completion auto-advances to `billing_pending` (§11.6) and creates the billing item. A missing required document is satisfied by an **accepted upload or an audited per-document "unavailable-with-reason" waiver** recorded inside the gated transition (clarify Q3). Billing values (planned/executed/adjustment/final) are a **computed projection** (`computeBillingValues`), never stored. Binaries live in **Supabase Storage** via the existing `packages/db/src/storage.ts` client (extended with `documents`/`billing-exports` buckets); uploads are validated to **PDF/JPG/PNG ≤ ~10 MB** (configurable, clarify Q4). The worker gains **two jobs** on the existing pg-boss queue (no new process): an **on-demand `billing.export`** (heavy ExcelJS xlsx/csv generation off the request path — no new dependency, since ExcelJS emits both) and a **scheduled `documents.checks`** sweep (the second scheduled job, ~5-min, lighting up the two §17 cases via the 007 `alerts` store). Authorization adds **no new permission key**: 008 **first-enforces** `upload_documents`, `verify_documents`, `mark_completed`, `mark_billing_ready`, `edit_rates`, `export_billing` and **reuses** `manage_commercial_data` for document requirements + the document-type master (reads stay on `view_all_trips`) — mirroring 004/`import_trips`, 005/`view_all_trips`, 006/`assign_resources`, 007/exception keys. Per the spec's clarifications, the gated business inputs are **documented configurable defaults, never invented** (Constitution II): per-customer required proof documents → `DEFAULT_DOCUMENT_CHECKLIST` + per-customer document-checklist sign-off blocked (§29 Input #3); the finance export format → a labeled default column set + export sign-off blocked (#4); per-customer billing rules (toll/waiting-time/penalty/cancellation) → manual values + billing-rule sign-off blocked (#5).
